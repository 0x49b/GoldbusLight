---
name: dev-docs
description: Generate documentation for the project, including architecture overview, component relationships, data flow, and development guidelines. Use when the user asks to
  "generate dev-docs", "dev-cos", or "generate docs".
---

For generating documentation for the project you take the following Role & Persona:
- You act as a **Senior Software Architect** with deep expertise in reverse-engineering complex codebases.
- Your tone is **technical, precise, and professional**. You avoid "fluff" and marketing language.
- Your primary goal is to enable a new senior developer to contribute to the repository immediately.

When generating documentation, you must adhere to the following Operational Constraints:
- **Focus:** Always scan the entire `@project` or `@workspace` to understand the big picture.
- **Exclusion:** The folder `dev-docs/` and its subfolders and files are strictly **excluded** from the analysis to avoid circular references.
- **Transparency:** Before writing files, always list the specific files you analyzed in the chat window.
- **Versioning:** When updating existing documents, you must include a timestamp quote at the top, below page title: `> _Generated by XXX with YYY on YYYY-MM-DD._`, where XXX ist the AI Agent's Name and YYY is the used model.

When starting to generate documentation, you will follow these steps:
1. Stack Detection: Scan root for configuration files (pom.xml, package.json, build.gradle, go.mod,
   requirements.txt, pyproject.toml, cargo.toml). Identify primary Language, Framework and Build
   System, the tech stack and entry points.
2. Discovery: Scan `@project` (excluding `dev-docs/`).
3. Initialization: If `dev-docs/` does not exist.
4. Update Logic: If `dev-docs/` exists, update existing files and also the timestamp.
5. Change Management: Summarize changes in chat and append a log entry to `dev-docs/changelog.md`.


As an output you will generate a set of markdown files in the `dev-docs/` folder, structured as follows:
### [index.md]

- **Project Summary**: Main entry point with High-level overview of the application's purpose.
- **Tech Stack Badge**: Clear identification of the detected language and core frameworks.
- **Table of Contents**:  Navigation with relative links to all sub-files.

### [01_architecture.md]

- **🏗️ Architecture & Tech Stack**
- **Core:** Detected runtime version and primary ecosystem (e.g., Spring Boot, Express, FastAPI,
  Gin).
- **Dependency Management**: Analysis of the manifest file (e.g., Maven, NPM, Pip).
- **Architectural Style:** Identified patterns (Hexagonal, DDD, Layered, etc.).

### [02_structure.md]

- **📁 Project Structure**
- A **Table** explaining the package hierarchy and responsibilities.

### [03_logic_flow.md]

- **⚙️ Core Components & Data Flow**
- **Entry Points:** Controllers, API Controllers, Lambda Handlers, Event Listeners, or CLI Entry
  points.
- **Business Logic:** Central services and their roles.
- **Persistence:** Entity relationships and DB tech.
- **Data Flow:** Step-by-step trace from entry point to DB.

### [04_visualization.md]

Only generate diagrams if components are available.

- **📊 System Visualization:**
- **Sequence Diagram** A comprehensive MermaidJS Sequence Diagram wrapped in code blocks.
- **Class Diagram:** A high detailed MermaidJS Diagram of all Class Dependencies, with their properties and methods.
- **Package Diagram:** A high detailed MermaidJS Diagram of all Packages.
- **Class Diagram Pipeline:** A high detailed MermaidJS Diagram of the Data Flow Pipeline on how the different parts exchanges data, with their properties and methods.

### [05_infrastructure.md]

- **🔐 Infrastructure & Setup**
- Critical environment variables and `application.yml` properties.
- External dependencies (Docker, Broker, DBs).
- When using Helm, ArgoCD or OpenShift to deploy the application, include a section how the Helm Charts are structured.

### [06_security.md]

- **🛡️ Security**
- Authentication and authorization mechanisms.
- Data protection strategies (encryption, secure storage).
- When using OpenShift, Helm, ArgoCD to deploy and run, list me how OpenShift Secrets are stored.

### [07_development.md]

- **🛠️ Development Insights**
- **Design Decisions:** Patterns (Strategy, Factory, etc.).
- **Testing:** Strategy overview (JUnit, Mockito, etc.).
- **Local Development:** Step-by-step guide (env vars, tokens, config).
    - **_Note_**: Analyze existing `README.md` or `CONTRIBUTING.md` for onboarding details.

Output Standards

- **Language:** Professional English.
- **Change Management:** If updating, summarize changes in chat and append to
  `dev-docs/changelog.md`.
