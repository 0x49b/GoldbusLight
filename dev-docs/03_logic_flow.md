# ⚙️ Core Components & Data Flow

The Goldbus Light Controller's functionality is orchestrated through a Go backend that exposes services to a React frontend, all encapsulated within a Wails desktop application.

## Entry Points

1.  **Go Backend (`cmd/goldbuslight/main.go`):**
    -   This is the primary entry point for the backend logic.
    -   It initializes the Wails runtime, sets up logging, and registers the Go services (`internal/service/goldbuslightservice.go`) that the frontend can call.
    -   It starts the main application loop, including background goroutines for tasks like device discovery and controller snapshot generation.

2.  **React Frontend (`frontend/src/main.tsx`):**
    -   This file bootstraps the React application.
    -   It renders the main `App` component (`frontend/src/App.tsx`) into the DOM.
    -   The frontend is served via Vite and runs within a Chromium webview provided by Wails.

## Business Logic (Go Backend)

The `internal/` package contains the bulk of the application's core logic:

-   **`internal/controller/controller.go`**:
    -   The central orchestrator. It manages the application's overall state (`ControllerSnapshot`).
    -   Coordinates interactions between various subsystems (WLED, DMX, Audio, Network).
    -   Handles persistence of settings and DMX fixture data.
    -   Manages device discovery and provisioning.
    -   Includes logic for "Party Mode" which synchronizes DMX output with audio input.

-   **`internal/wled/engine.go`**:
    -   Responsible for communication with WLED devices.
    -   Sends HTTP requests to WLED devices to control their state (brightness, color, effects).
    -   Parses WLED device responses and status information.

-   **`internal/dmx/artnet_packet.go` / `dmx_live_output.go`**:
    -   Handles the creation and sending of Art-Net DMX packets over UDP.
    -   Manages the live DMX output loop.

-   **`internal/serial/`**:
    -   Manages communication with USB-to-DMX serial devices.
    -   Provides platform-specific implementations for Linux, macOS, and Windows.
    -   Sends DMX universe data over the serial port.

-   **`internal/audio/capture.go` / `features.go`**:
    -   Manages audio input capture from the system.
    -   Performs real-time audio analysis (e.g., FFT) to extract features like beat, bass, mid, and treble for "Party Mode".

-   **`internal/network/`**:
    -   Provides platform-specific interfaces for controlling network settings (e.g., setting up an access point).
    -   Interacts with system-level CLI tools (`nmcli`, `networksetup`, `netsh`).

-   **`internal/console/console.go`**:
    -   A ring buffer for logging internal events and communications, accessible by the frontend.

-   **`internal/service/goldbuslightservice.go`**:
    -   This package exposes Go functions to the Wails frontend. Functions here correspond to the Wails-generated TypeScript bindings in `frontend/src/bindings/`.

## Persistence

Application settings and DMX fixture configurations are persisted as JSON files.
-   The `ControllerSettings`, DMX fixture data, and general UI state are serialized to disk.
-   The `claude-kmp.md` document mentions JSON files in `UserConfigDir` (macOS `~/Library/Application Support`, Linux `~/.config`, Windows `%APPDATA%`).

## Data Flow

1.  **Frontend Action:** The user interacts with the React UI (e.g., clicks a button to change a WLED device's color, edits a DMX fixture).
2.  **Wails IPC Call:** The React component calls a corresponding Go function via the Wails-generated TypeScript bindings (e.g., `GreetService.SetDeviceState(...)`).
3.  **Go Backend Processing:** The Go function in `internal/service/goldbuslightservice.go` receives the request.
    -   It might interact with the `internal/controller` to update application state.
    -   The `controller` then dispatches actions to relevant subsystems (e.g., `internal/wled` to send an HTTP command to a WLED device, `internal/dmx` to send DMX data).
    -   Any events or logs from these subsystems might be routed through `internal/console`.
4.  **State Update & Notification:** The `internal/controller` updates its `ControllerSnapshot` and emits an event.
5.  **Wails Event to Frontend:** The Wails runtime catches this event (e.g., `controller:snapshot`) and pushes it to the frontend.
6.  **Frontend Reactivity:** The React application (specifically `frontend/src/hooks/useControllerApp.ts` which uses a Zustand store) subscribes to these events and updates its internal state, triggering a re-render of the UI to reflect the new application state.

This cycle ensures that user actions are processed by the backend and reflected in the frontend in real-time.
