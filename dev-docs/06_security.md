## Data Protection Strategies

-   **Configuration Files:** Application settings, including network configurations and DMX fixture data, are stored locally as JSON files. These files are typically located within the user's configuration directory (e.g., `~/.config` on Linux, `~/Library/Application Support` on macOS, `%APPDATA%` on Windows).
    -   **Exposure Risk:** Sensitive information (e.g., Wi-Fi passwords for access point mode) stored in plain text JSON could be vulnerable if the user's system is compromised.
    -   **Mitigation:** Users should be advised to secure their operating system and limit access to these configuration files. Encryption of sensitive fields within the JSON could be a future enhancement if required.
-   **Network Communication:**
    -   **WLED:** Communication is via HTTP, which is unencrypted unless WLED devices are configured for HTTPS. The application currently assumes unencrypted HTTP for WLED control.
    -   **Art-Net/UDP:** Art-Net uses UDP, which is inherently unencrypted and connectionless. It's suitable for local network DMX control but not for untrusted networks.
    -   **USB Serial:** USB-DMX communication is local to the machine and generally considered secure within the device's physical perimeter.
-   **Process Execution:** The `internal/network/` package executes system-level commands (`nmcli`, `networksetup`, `netsh`). This introduces a dependency on the security of the underlying OS commands and the environment in which they run. Malicious injection into these commands could be a risk if not properly sanitized, though standard practices in Go's `os/exec` would typically prevent this.
